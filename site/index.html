Zyvor · device OS updates

Signed A/B updates. Commit or roll back.

The open OTA runtime for Linux edge fleets: signed updates, automatic rollback, offline operation and verifiable deployment evidence, without cloud lock-in. Fleet decides which devices and when. OTA verifies and installs. RAUC writes the inactive slot.

Why Zyvor OTA

Each row is a field problem and what the README says the agent does about it.

An update image could be tampered with or replayed

Ed25519-signed exact-byte release envelopes, pinned device trust keys, expiry, a monotonic release sequence and replay rejection.

A bad update bricks devices

Install to the inactive RAUC A/B slot, run a local health window, then mark good or roll back automatically.

The agent crashes mid-install

A durable SQLite (WAL) journal and an explicit NeedsRecovery interlock for ambiguous outcomes.

Sites have slow, metered or no WAN

Resumable HTTPS downloads, download windows, bandwidth caps, offline campaign media and a site relay client.

Security won't accept an inbound port

An outbound-only Fleet contract over TLS or mTLS, polling with ordered event acknowledgment.

An auditor asks what was installed

Prometheus metrics, optional OpenTelemetry spans, a signed SBOM check and an append-only release log.

What it does

Verify

  • Ed25519 envelopes over exact bytes, pinned device keys
  • SHA-256 and signed artifact sizes, exact board and backend compatibility
  • Expiry, monotonic sequence, job idempotency, maintenance windows
  • Optional threshold root, delegated targets, signed SBOM, release log

Install and survive

  • RAUC InstallBundle, Completed, GetSlotStatus, GetPrimary and Mark over D-Bus
  • Controlled reboot, local health window, mark-good or rollback
  • File, systemd-service and loopback HTTP health probes
  • No shell commands or arbitrary update scripts accepted

Offline and constrained sites

  • HTTPS downloads with host allowlists, bounded size, disk reserve and resumable ranges
  • Offline campaign export and import, local media, jitter
  • Site relay client

Operate

  • otactl CLI over a Unix-socket operator API (zyvor-ota is an alias)
  • Prometheus text metrics, optional OpenTelemetry spans
  • Schema 2 typed targets (os.rauc, container.oci, config.bundle, model.oci) commit or roll back as one set

How it fits together

Fleet decides which devices and when. The agent verifies and installs. RAUC writes the inactive slot and integrates with the board bootloader. There is intentionally no second fleet dashboard or rollout controller in this repository.

Maturity, stated plainly.

v0.2.0 is an engineering preview: a working agent, CLI, RAUC adapter, simulator and CI, plus a complete generic QEMU RAUC lab HIL. Minewing silicon qualification is still unsigned. Not claimed: physical Minewing RAUC or power-loss qualification, Uptane conformance, a TPM driver, SWUpdate .swu, MCU firmware or bootloader updates. Evidence is in the verification report and the roadmap.

Quickstart

Requires Linux, Go 1.27.1 or a newer supported patch (Go 1.24 is the language minimum), Python 3 for the demo, GCC for race tests and dbus-daemon for protocol tests. These are the README's commands.

1. Build and run the simulator demonstration

make build
make test
make demo

The demo starts the real daemon and CLI against a local artifact server, installs two simulated releases, commits the first, rolls back the unhealthy second, and rejects replay. It never writes disks, calls system reboot or contacts a Fleet deployment.

2. Sign a release and submit it

otactl keygen ./release-keys
# Fill examples/release.json with the actual artifact URL, SHA-256, size and expiry.
otactl sign release.json release-keys/release.key production-1 envelope.json
# Embed envelope.json as the release field in assignment.json.
otactl -socket /run/zyvor-ota/agent.sock submit assignment.json
otactl -socket /run/zyvor-ota/agent.sock job job-001

Keep the signing private key off the device. Before using the RAUC backend on hardware, read device integration: the image must already provide redundant slots, a bootloader fallback policy and a recovery method. The guided tutorial walks the 15-minute trial.
